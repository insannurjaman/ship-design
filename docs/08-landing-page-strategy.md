# 08 Landing Page Strategy

## Purpose

This document defines the landing page strategy for Ship Design.

The landing page should explain the product clearly and show why it is useful for turning product ideas into design-ready artifacts.

## Primary Audience

The first landing page should speak to:

- Founders with product ideas
- Product designers starting new projects
- Small product teams preparing MVPs

## Core Message

Ship Design turns one product idea into a structured product design package.

## Positioning

Ship Design is not just a chatbot and not just a design generator. It is a guided agent system for product design planning.

It helps users move from:

> Rough idea

To:

> Strategy, research, flows, screen inventory, Figma structure, design system, prototype plan, landing page strategy, and developer handoff.

## Hero Strategy

The first viewport should immediately signal:

- Product name: Ship Design
- Product category: AI-powered product design agent system
- Main outcome: turn an idea into a design package
- Visual style: dark technical workspace with acid green system signals

The hero should show the actual product experience or a believable product workspace, not a generic abstract illustration.

## Suggested Page Sections

1. Hero
2. Product output preview
3. How the agent system works
4. Artifact list
5. Figma and developer handoff value
6. Use cases
7. Quality and consistency promise
8. Call to action

## Messaging Pillars

| Pillar | Meaning |
| --- | --- |
| From idea to structure | Helps users organize messy product thinking |
| Design-ready artifacts | Produces practical outputs, not vague advice |
| Agent-based workflow | Specialized agents handle different design tasks |
| Figma-ready planning | Structures work so designers can continue in Figma |
| Better handoff | Gives developers clearer context |

## Example Headlines

- Ship Design
- Turn one product idea into a complete design package
- Product design planning, powered by focused AI agents

## Example Supporting Copy

Ship Design helps founders, designers, and product teams turn a rough idea into strategy, UX research, flows, screens, Figma structure, design system direction, prototype planning, landing page strategy, and developer handoff.

## Visual Requirements

The landing page should follow the same visual direction as the product:

- Dark background
- Acid green accent
- Crisp 1px borders
- Grid layout
- Mono labels
- Technical status details
- Real product UI previews

Avoid:

- Generic SaaS gradients
- Friendly blob illustration
- Soft rounded cards everywhere
- Vague AI magic language

## Call To Action

Primary CTA:

> Start a design package

Secondary CTA:

> View example output

## Landing Page Success Metrics

- Visitor understands the product within 5 seconds.
- Visitor can name the main output.
- Visitor clicks the primary CTA.
- Visitor views an example design package.
- Visitor starts a new project.

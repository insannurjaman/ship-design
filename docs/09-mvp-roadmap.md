# 09 MVP Roadmap

## Purpose

This roadmap breaks Ship Design into practical build phases.

The goal is to reach a useful MVP without trying to build every agent, export, and collaboration feature at once.

## Phase 0: Project Brain

Status: Current phase

Goals:

- Define the product concept.
- Define requirements.
- Define agent roles.
- Define user flows.
- Define screen inventory.
- Define design system direction.
- Define Figma structure.
- Define quality checklist.
- Define landing page strategy.

Done when:

- All project brain docs exist.
- The team can explain what Ship Design is.
- Codex and Figma have enough guidance for the next phase.

## Phase 1: Text-First Prototype

Goals:

- Create a simple guided workflow.
- Accept one product idea.
- Ask clarifying questions.
- Generate text artifacts.
- Show artifact review screens.

Core features:

- New project intake
- Project brief generation
- Artifact generation
- Artifact list
- Artifact detail view
- Basic decision log

Done when:

- A user can enter an idea and receive a complete text-based design package.

## Phase 2: Structured Agent Workflow

Goals:

- Separate agent responsibilities.
- Add stronger shared project memory.
- Add artifact dependencies.
- Add QA checks.

Core features:

- Agent status overview
- Per-agent outputs
- Shared project brief
- Open questions
- Consistency checks
- Regeneration controls

Done when:

- Generated artifacts feel consistent and traceable.

## Phase 3: Figma-Ready Output

Goals:

- Prepare outputs for Figma creation.
- Define page, frame, and component structures.
- Support designer-friendly naming and organization.

Core features:

- Figma page plan
- Frame inventory
- Component inventory
- Prototype path map
- Handoff annotations

Done when:

- A designer can recreate or automate the design package in Figma using Ship Design output.

## Phase 4: Visual Product Workspace

Goals:

- Build the full product UI.
- Apply the dark technical design system.
- Improve navigation and review workflows.

Core features:

- App shell
- Sidebar navigation
- Artifact workspace
- Agent progress panel
- Review and approval states
- Export center

Done when:

- The product feels like a usable design command center.

## Phase 5: Landing Page

Goals:

- Explain the product publicly.
- Show a believable product preview.
- Drive users into project creation.

Core features:

- Hero
- Product output preview
- Agent workflow explanation
- Use cases
- CTA

Done when:

- A visitor understands Ship Design and can start or request access.

## Phase 6: Developer Handoff

Goals:

- Make outputs more useful to engineers.
- Connect screens, states, components, and data needs.

Core features:

- Feature specs
- Screen state specs
- Component usage notes
- Data requirements
- Edge cases
- Exportable handoff docs

Done when:

- A developer can understand what to build from the generated package.

## Later Opportunities

- Direct Figma file generation
- Multi-project workspace
- Team collaboration
- Version history
- Design critique agent
- Competitive research agent
- Product analytics integration
- Code handoff integration
- Template library by product type

## MVP Principle

The MVP should prove that Ship Design can reliably turn one idea into a useful product design package.

Everything else can wait.
